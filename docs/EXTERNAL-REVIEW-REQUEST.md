# Q-Tape M3.2 External Security Review Request

This document is the handoff request for an **independent** reviewer. Q-Tape internal tests and the static guard are not a substitute for this review.

## Review target

- Repository: https://github.com/novus77/q-tape
- Branch/commit: fixed by the archive manifest (`REVIEW-MANIFEST.json`)
- Review package: generated by `bun scripts/prepare-review-package.ts`
- Primary scope:
  - `contracts/src/Guardian.sol` / `contracts/src/interfaces/IProtocol.sol`
  - `packages/schema/src`, `packages/protocol/src`
  - `packages/signer/src`, `packages/signer/native/falcon_signer.c`
  - `packages/client/src` (profile/inspection/planning/readback)
  - `apps/relayer/src`, `apps/web/src`
- Out of scope: external TapeOut proxy upgrades, mainnet deployment, real asset custody; PQClean/fndsa cryptographic implementation audit is requested as a dependency-risk review, not a reimplementation audit.

## Reviewer qualifications

- Solidity/EVM application security, including upgradeable external protocol assumptions and calldata canonicalization.
- Post-quantum signature integration (Falcon-512/PQClean) and native process/key-handling review.
- TypeScript/Bun security review and dependency/supply-chain review.
- Ability to reproduce the fixed-fork tests and report findings with severity, evidence, and remediation verification.

## Required deliverables

1. Written report bound to the exact commit and archive hash.
2. Findings with severity (Critical/High/Medium/Low/Info), reproduction, and affected files.
3. Confirmation that `bun install --frozen-lockfile && bun run bootstrap && bun run check && bun run test:fork && bun run test:m2 && bun run test:m3` either passes or explain environment limitations.
4. Re-test of fixes (a second report or signed addendum).
5. Explicit statement of residual risks and out-of-scope items.

## Process

1. Review package is generated on a clean commit; reviewer verifies the manifest hashes.
2. Kickoff: threat model, acceptance record, known limitations, test commands.
3. Reviewer performs manual review + dynamic/adversarial testing + dependency review.
4. Findings triage: Critical/High block M3.3/M3.4; Medium/Low need written acceptance or fix.
5. Fix cycle: commit fixes, rerun full tests, update `docs/SECURITY-REVIEW-M2.md` (or M3 review record) with evidence.
6. Reviewer signs the final report and re-test addendum.
7. Only then record M3.2 complete and consider M3.3/M3.4.

## What Q-Tape provides

- `docs/THREAT-MODEL.md`, `docs/SECURITY-REVIEW-M2.md`, `docs/SECURITY-REVIEW-PREP.md`

## What Q-Tape does not claim

- No audit has been completed.
- Internal review, fuzzing and happy-dom tests do not replace independent review.
- No mainnet deployment, real NFT migration or user-key custody exists in the review package.
